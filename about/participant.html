Where we lose

This site is published by the sgit project, and it reports on the sgit project's own network. That is a participant's position, not a press's, and it is worth stating before anything else on the site is read. What follows is the part a participant usually leaves out: where this is not, and cannot be, an independent newsroom.

Four cases where "newsroom" is the wrong word

1 · No editorial distance

An independent newsroom can report unfavourably on a subject without consequence to itself. This site cannot: it is written by the same project as every site in its beat. The first story's correction is about a stale hostname, not a hard editorial call — this site has not yet been tested on a story where the honest report reflects badly on a sibling, and has no track record either way.

2 · No outside sources

Every fact on this site so far comes from a *.sgit.ai repository's own files, read directly. There is no independent verification, no second source, no reader tip line, and no mechanism for one yet. A number reported here is only as reliable as the repository it was read from being accurate about itself.

3 · No standing corpus of stories

One story exists. A newsroom's value is mostly in the pattern across many stories over time — catching a trend, holding a site to what it said last release. At one story, there is no pattern to catch yet; treat this site's coverage as a first data point, not a track record.

4 · No brief pack, no set scope

Unlike every sibling site, this one was not built from a commissioned, dated source pack. That gap is open request N1. Until it closes, what this site chooses to cover is this release's own judgment call about what was checkable and real, not a scope somebody else set and reviewed in advance.

And one thing about this release specifically

  • v0.1.0 shipped without a brief. Every other *.sgit.ai site's admin page can point to the pack it was built from; this site's admin page states plainly that no such pack exists yet, rather than presenting the current three-section scope as considered and final.

Where it does hold up, for balance

  • Every checkable fact is checked against a primary source, not against another *.sgit.ai page. The first story states the method and the exact commands used, so a reader can re-run them.
  • A discrepancy was found and reported, not smoothed over, on the very first pass — including one about how a sibling site describes this site's own newest neighbour.
  • The participation is disclosed on every page, not buried in a footer link nobody follows — every footer on this site carries the same one-line disclosure this page expands on.

How to check this site rather than trust it

Every load-bearing fact here was measured, and every measurement can be re-run:

curl -s https://raw.githubusercontent.com/SGit-AI/<repo>/dev/CNAME
curl -s https://raw.githubusercontent.com/SGit-AI/<repo>/dev/admin/build/version.txt

A site written by a participant should be checkable, since it cannot be neutral.
