Release history

Every push to dev is a release: CI validates the site, verifies the version bump, tags the commit v{release}.{major}.{minor}, and deploys to GitHub Pages. The version is owned by admin/build/version.txt and must agree with the release commit's subject. How it works.

VersionDateWhat shipped
v0.1.0 22 Aug 2026 The site, first release — pipeline first, same order issues-fs.sgit.ai shipped v0.1.0 in.

The pipeline before the content. Validate → auto-tag → deploy, carried in unchanged from issues-fs.sgit.ai, which carried it from graphs.sgit.ai and pki.sgit.ai, whose own history traces the pipeline's root to the VoiceDebrief website pipeline — reported in full on the first story. No content-specific tripwires were invented for v0.1.0 that the site could not yet back with real checked facts; the gate runs the shared core — version agreement, links, canonical, the agent surface, key-leak, block balance — plus the agent-block rule inherited from issues-fs.sgit.ai.

No brief pack exists for this site yet — unlike sgit.ai, pki.sgit.ai, graphs.sgit.ai and issues-fs.sgit.ai, each commissioned against a dated source pack before their first page was written. Rather than invent scope or fabricate a corpus, v0.1.0 ships the smallest real thing: three sections built from facts checked directly against six sibling repositories on 22 August 2026, published in the first story, with the roles that do the checking stated on their own page and the boundary with every sibling stated on the network page. This is recorded as open request N1, not silently worked around.

One real correction shipped with the first story: issues-fs.sgit.ai's own network page names a sibling sentinel.sgit.ai; the actual repository, checked directly, ships CNAME sg-sentinel.sgit.ai. It is the first instance of the sourcing discipline this site is built to apply — check the primary source, not the sibling's claim about it — turning up something real on the very first pass.
