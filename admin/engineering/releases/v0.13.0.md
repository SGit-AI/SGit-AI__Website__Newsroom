# v0.13.0: the reader code moves to api.newsroom.sgit.ai

Phase 1 of [Go slow to go fast](../../articles/explorer-to-villager-newsroom.html). Everything a reader runs in the browser, the meter (v1.4.1 and the frozen v1.0.0 to v1.4.0), the component base, the reading lists, subscribe, the vault layer and the pane, search and ask, the wire reader, the vendored vault library and the passkey lab, 74 files, left this repository for [SGit-AI__Website__Newsroom__API](https://github.com/SGit-AI/SGit-AI__Website__Newsroom__API) and is served from `https://api.newsroom.sgit.ai/v0.2.0/<path>`, at the paths the files had here. Every page, imported or written here, loads it from that host and never by a relative path; `admin/build/api.json` pins the release, `api-manifest.json` is that release's manifest, and `admin/build/api.py` writes, checks and can re-point every reference. A rollback is the previous release in the pin and one run of `--repoint`.

The same bytes, proved by hash. The brief's rule for the move is that the live site serves the same bytes before and after, and the proof is in the API repository (`map/proof/`): the 74 files hash raw as they did here at v0.12.10, apart from three that the host forced to change, each by the lines that took the site root from the script's own address and now take it from the page (`vault-pane.js`, `search.js`, `ask.js`; recorded file by file in the release manifest); and every page normalises to what it was, with one rule added to the normaliser that check 11 already used for imported pages: a reader-file reference, relative or on the host, reads as `API/<path>`.

What a reader does not notice: their balance, personas, notes and lists are in this origin's storage and stay there, because storage belongs to the page and not to the script; the meter still fetches the article feed and the contact file from this site; every address stays. The frozen meter versions stay here too, byte-identical to the host's (check 13), until phase 4. The tests moved with the code and run there, in Chromium, WebKit and Firefox, against this site's pages; this repository's gate checks the pin (check 14) and no longer runs them. sgit.ai pins the same release next, and then the sync carries no reader code at all (its items 11 and 14).
