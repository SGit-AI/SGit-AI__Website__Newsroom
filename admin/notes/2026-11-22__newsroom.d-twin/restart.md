# Restart: how a new session of d.newsroom takes over

1. **Registration.** writer-11's private key lives only in the old container. A new session cannot sign as writer-11. Ask Dinis, in the new session, to close writer-11 and open the next id (as writer-09 handed to writer-10, `admin/notes/2026-11-18__writer-09-handover/DEBRIEF.md` section 0). Opening needs two commits: one that is not a writer commit adds the registration, then a writer commit publishes `git_signing` (memo-02 here explains why).
2. **Read** `role.md`, then `now.md`, `agent.json` and `CLAIMS.md` here, then the debriefs and memos 01 to 04.
3. **Environment** (scratchpads are wiped): clone `SGit-AI/SGit-AI__Website` read-only beside this repository (`git remote set-url --push origin no_push`); `git fetch --unshallow`; in a scratch folder `npm install sharp jsqr@1.4.0` and symlink the pre-installed Playwright into its node_modules (npm's own Playwright cannot find the container's Chromium); `pip install sgit-ai==0.21.0` (the version CI uses). Copy `tools/gate.sh` and fill in the two attribution lines.
4. **Release** as the handbook's eleven steps: pending version, install, `release.sh` in the background, `summaries.py --stamp/--check`, width 390 on every new article (wide tables break it), the gate, wait for CI's `site vX` commit, check live.
5. **Known failures:** `test_reading.mjs` fails locally (environmental); a stale front page (the agent note naming an old version) fails `test_front` on CI until `front.py` and `chrome.py` are rerun; GitHub Pages sometimes reports "No artifacts named github-pages", and the next push deploys.
