# Research 1: what the cloud providers give an agent (29 October 2026)

*A research agent of newsroom.writer's session. H: fetched, word for word (Google quotes are fragments from the
fetch tool; re-check before quoting more). M: secondary. U: not verified. Absences are "the documentation does not
describe", from the pages fetched.*

- Microsoft Entra Agent ID (H, learn.microsoft.com/en-us/entra/agent-id/whats-new-agent-id, 2026-05-01): "Microsoft Entra Agent ID is now generally available."; "Agents can request access tokens from Microsoft Entra, and use those tokens to access web services." (what-are-agent-identities); "Agent identities don't have credentials of their own." and "Credentials do *not* reside on the agent identity." (agent-identities); "Agent identities can only be issued tokens in the Microsoft Entra tenant where they're created."; "The identity model is designed for scale and ephemerality rather than permanence."
- AWS Bedrock AgentCore Identity (H, docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html): "an identity and credential management service designed specifically for AI agents and automated workloads"; agent access token "An AWS-signed token that contains both workload identity and user identity information"; token vault keys: only "single-region symmetric KMS keys", "asymmetric keys" not supported; the agent identity directory organises identities "within an account or region"; "Each runtime session runs with the execution role credentials configured on the agent runtime."
- Google Cloud Agent Identity (H, docs.cloud.google.com/iam/docs/agent-identity-overview, updated 2026-10-27): "An X.509 certificate is auto-provisioned and managed on the agent"; "Each X.509 certificate is valid for 24 hours, and Google Cloud automatically keeps it current"; certificates "chain up to a Google-managed root certificate authority (CA)"; "An agent's identity is derived from the ID of the resource that hosts it."; only the CA certificates are published.
- Anthropic Workload Identity Federation (H, platform.claude.com/docs/en/manage-claude/workload-identity-federation): "Workload Identity Federation (WIF) lets your workloads authenticate to the Claude API with short-lived OpenID Connect (OIDC) tokens instead of long-lived `sk-ant-...` API keys."
- OpenAI: nothing found per agent or per session (U).
- IETF draft-ietf-wimse-aims-00, "AI Identity Management System", 15 Sep 2026, authors from Defakto, AWS, Zscaler, Ping, OpenAI, Okta (H): "An agent participating in this framework MUST be assigned exactly one WIMSE identifier, which MAY be a SPIFFE ID."; "Static API keys are an antipattern for agent identity."; "Agents MUST possess credentials that provide a cryptographic binding to the agent identifier."; "Agent credentials SHOULD be short-lived to minimize the risk of credential theft,". It defines no encryption to an agent's key and no agent key directory.
- OpenID Foundation whitepaper "Identity Management for Agentic AI", 7 Oct 2025 (H, openid.net/new-whitepaper-tackles-ai-agent-identity-challenges/): "current authentication and authorization standards are already capable of securing many of today's AI agent use cases."
