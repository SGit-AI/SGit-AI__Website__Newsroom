The vault is live: from a design on 11 October to a reader's vault on newsroom.sgit.ai by two in the morning, and how all of it fits together 2026-10-12

  • definitionRecords, never totals, one file per device: each device writes what it originated to its own file, whole, totals are recomputed on every open, and two devices never write the same file, so there is nothing to merge.“Two devices never write the same file, so there is nothing to merge.” § sync
    Records, never totals 3Vault design 48
  • factThe reader vault holds an account file written once, one file per device rewritten whole on each sync, and a notes folder where the lab wrote its first note.“one per device, rewritten whole on each sync” § chain
    Records, never totals 3The vault 108
  • factThe vault holds records because a total copied from a device would be wrong the moment a second device existed; reads, spend, declined, credit and balance are recomputed from the records every time they are shown.“A total copied from a device would be wrong the moment a second device existed.” § sync
    Records, never totals 3Micropayments and the reading meter 41
  • factThe consolidated view is computed, not stored: brought-in records are tagged with the device they came from and the next sync writes only the browser's own records back, so a record has exactly one author for ever.“so a record has exactly one author for ever” § sync
    Records, never totals 3Vault design 48
  • factTop-ups are counted once by payment reference so a return page opened on a second device cannot credit it twice, and the keys of an unlocked session are kept in memory and the tab's session storage for the life of the tab.“Top-ups are counted once by payment reference” § sync
