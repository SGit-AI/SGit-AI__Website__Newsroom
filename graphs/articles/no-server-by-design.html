Facts (17)

  • factA database server is a large, stateful, always-on thing to provision, secure, back up, migrate and pay for whether or not anyone uses it, and most of what it holds would be happy as files; Issues-FS applies the same idea to an issue tracker.“Load the state, work on it in memory, save it back: that is a cache, a database and an audit trail in one, and git gives it history for free.” § files
    LETS: Load, Extract, Transform, SaveIssues-FS 8Git 17
  • factIn September the newsroom ran two real database engines, SQLite and a SPARQL store, compiled to WebAssembly in the reader's browser over the Portugal section's JSON files; the build runs every example query and fails if one returns nothing.“The database is the files; the engines are just readers.” § files
    Client-side and on-device 56SQLite 6OxigraphWebAssemblyThe SGit Newsroom 72
  • factA vault is encrypted in the client before it leaves, the server stores ciphertext in S3 and never sees a key, read keys are derived one way and can be published, and append lanes let anything write an entry readable only by the owner.“by design, the server side cannot see anything” § backend
    The vault 108Vault design 48Encryption and keys 70sgit 91
  • factThe client-side architecture was not chosen and then given encryption; encryption came first and the architecture followed, because a feature that reads the reader's data has to run where the key is, in the browser.“Encryption came first, and the client-side architecture followed, because there was nowhere else for the logic to go.” § backend
    Client-side and on-device 56Encryption and keys 70
  • factThe newsroom today lands a reader as a persona, builds personas from reading, charges by the share of a page read, takes a £5 Stripe payment, keeps a reading history, shows versions and runs SQL and SPARQL, all in the browser or built in CI.“There is no account database, no session store, no API server and no back end to deploy.” § newsroom

    Wardley maps 24Client-side and on-device 56The code you do not ship 18
  • factA hundred thousand readers mean a hundred thousand browsers each doing their own work against a server side serving cached static files and ciphertext; the server's work grows with bandwidth and its complexity does not grow at all.“The server side's work grows with bandwidth, which is the cheapest thing on the internet to buy. Its complexity does not grow at all.” § scale
    Client-side and on-device 56Complexity and shipping 60
  • factSG Meter's security model lists the gaps a client-side design leaves, and every gap is accepted: a reader can edit their balance, start again in a private window, credit themselves through an unprotected page, or clear a negative balance; agents read the twins unmetered.“A design with no server has security gaps, and the honest thing is to list them.” § security

    Risk acceptance 37Client-side and on-device 56The code you do not ship 18
  • factFive synthetic readers found no security problem but found the design from the reader's side: credit below zero reads as a debt, and a top-up page that says the cart is simulated while asking for money leaves a careful reader unsure.“none of them found a security problem” § security
    Synthetic users 26SG Meter 26
  • factBecause everything the owner builds is open source there is no moat to keep using, so every component is asked whether it still earns its place, and open source removes the one bad reason to say yes: that he built it.“open source removes the one bad reason to say yes: that I built it” § openness
    Open source and open licences 53The code you do not ship 18Memory-FS
  • factA release is a set of files: no schema migration, no server to deploy, no compatibility window between an old back end and a new front end, and rolling back is a commit.“There is no schema migration, no server to deploy, no compatibility window between an old back end and a new front end, and rolling back is a commit.” § speed
    Complexity and shipping 60Client-side and on-device 56Deployment and self-hosting 21
  • factThe pattern ties in with sovereignty, the reader holds the data and keys; privacy, the server cannot read what it does not have; explainability, the whole application is files; and determinism, the same files give the same result.“Not as a policy, but as a property: the server cannot read what it does not have, and the vault server cannot read what it stores.” § principles

Hypotheses (1)

  • hypothesisThe next major pattern of the owner's architecture is retiring the back end: the application is files a browser downloads, the state lives in the browser or an encrypted vault, and the servers are products rented, not run.“First I retired the database. Now I am retiring the back end.” § top
    Client-side and on-device 56The code you do not ship 18The vault 108

Proposals (1)

  • proposalNext: a model in the client with the reader's own key, personas that follow the reader to every device and agent through a vault, a signed receipt for payments, and the newsroom's architecture packaged as a template for any content site.“the newsroom's architecture packaged so that another publication, or any content site, can start from it” § next

Questions (1)

  • questionHow far can the pattern be pushed: payments need a signed receipt verified in the browser, identity client-side OAuth or passkeys unlocking a vault key, cross-device personas a vault, readers writing to us append lanes, models in the client, search a static index.“Here is my current list of what still seems to need a server, and what covers each without one of mine.” § push
    Client-side and on-device 56Identity and secrets 59WebAuthn and passkeys 15Vault design 48

Definitions (1)

  • definitionLETS, Load, Extract, Transform, Save, is a deliberate change to ETL from a May 2025 paper: every stage reads and writes files, every intermediate state is kept, and the file system or object store is a first-class database.“every stage reads files and writes files, every intermediate state is kept, and the file system, or an object store, is treated as a first-class database” § files
    LETS: Load, Extract, Transform, SaveMemory-FSMyFeeds 3The Cyber Boardroom 7

Decisions (2)

  • decisionThe owner's long-standing rule is not to use a database: the file system is the database, and loading files, working on them and saving them back is simpler, cheaper and easier to reason about than a database server.“The file system is a powerful database, and loading files, working on them and saving them back is simpler, cheaper and easier to reason about than running a database server.” § top
    LETS: Load, Extract, Transform, SaveThe code you do not ship 18
  • decisionThe owner's security experience is what lets him deploy a system with gaps, because the gaps do not match the audience; what is protected is the reader's own history, which never leaves their browser unless they send it encrypted.“the gaps do not match our audience” § security
    Threat modelling 15Risk acceptance 37Privacy and sovereignty 45Dinis Cruz 126

Limits (5)

  • limitThe meter's model says what would change the call: if the balance ever unlocked something, the gaps would stop being acceptable and that feature would get a signed receipt or a server, and not before.“if the balance ever unlocked something, the gaps would stop being acceptable” § security
    Risk acceptance 37SG Meter 26
  • limitThe one real limit is anything the reader must not hold: a shared API key or a price that must not be editable because it unlocks something cannot live in the browser, and needs a signed artefact or a small commodity function.“The one real limit: anything the reader must not hold cannot live in the reader's browser” § push
    Client-side and on-device 56Identity and secrets 59
  • limitNot that servers are bad: some applications, a trading system, a multiplayer game, a bank's ledger, need shared, live, authoritative state; this pattern is for applications where each user's state is theirs.“This pattern is for applications where each user's state is theirs.” § limits
    Client-side and on-device 56
  • limitNot that the gaps are free: they are accepted because of who reads this site and what the meter protects, and a different site with a different threat would make a different call.“A different site, with a different threat, would make a different call, and the security model says what would change ours.” § limits
    Risk acceptance 37Threat modelling 15
  • limitNot that it is finished: sign-in, cross-device personas, a model in the client and signed receipts are next, not done.“Sign-in, cross-device personas, a model in the client and signed receipts are next, not done.” § limits
    Client-side and on-device 56Personas and personalisation 33
