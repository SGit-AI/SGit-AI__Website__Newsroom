The article: Code review as a fractal semantic graph: source code is already one, and the review should read every layer of it (2026-10-03). Every claim below is the article's own, in plain words, with the sentence it rests on and a link to its section.

Facts (13)

  • factEach layer is a different universe: component edges are imports and data flows, class edges are field types and inheritance, method edges are calls, syntax-tree edges are the grammar, and none of these vocabularies should be forced to be the others.“None of these vocabularies is the others, and none should be forced to be.” § top
    Fractal semantic graphs 62Source code as a layered graphMeaning through connectivity 24
  • factSimon Brown's C4 model, named in 2011, names four levels, context, container, component and code, and calls the fourth optional because IDEs can generate it; the real thing has levels of levels below the component.“The trouble with a fixed four is not that four is wrong. It is that the real thing has levels of levels” § top
    Simon BrownThe C4 modelSource code as a layered graph
  • factGherkin, created by Aslak Hellesøy in 2008, forced the top layer into Given, When, Then, but the glue underneath was a regular expression matching step text to code, the right top layer with nothing beneath it.“The step text was matched to code by a regex” § top
    GherkinAslak HellesøySource code as a layered graph
  • factThreat modelling is a third witness: data flow diagrams decompose hierarchically and STRIDE assigns threats by node type, so threat modellers have drawn a fractal graph of the system by hand for twenty years, at one altitude.“Threat modellers have been drawing a fractal graph of the system by hand for twenty years, at one altitude, and leaving the rest unconnected.” § top
    Threat modelling 15OWASP 13Microsoft 27Source code as a layered graph
  • factThe syntax tree, not the text, is the right starting point, and a January 2026 paper found deterministic AST-derived graphs give more reliable coverage than LLM-extracted graphs at far lower indexing cost: derive what a parser can, spend the model on the rest.“derive what a parser can derive, deterministically, and spend the model on what the parser cannot know.” § top

  • factEvery source file produces a pile of JSON files, classes, methods and calls, package graph, fingerprint, tests and rules, kept beside the code in a git repository or a vault, regenerated only on change so the cost scales with the change.“so you generate it once and regenerate on change, and the cost scales with the change rather than the repository.” § top

  • factA code review today reads a text diff at the altitude of lines, which is the wrong one for almost every question a reviewer has: does this change user behaviour, is it the fix it claims, what else can it reach.“The diff is at one altitude, the lines, and it is the wrong one for almost every question a reviewer actually has.” § top

Hypotheses (4)

  • hypothesisWhat changed is that naming is cheap: a language model can read a function, say what it does, name the story a command serves and propose the verb between two nodes, as a structured file validated against a schema rather than prose.“Naming used to be the expensive part.” § top
    Source code as a layered graphFractal semantic graphs 62
  • hypothesisWhat makes it work is reality, not accuracy: the graph need not be right, it must be made of layers someone knows and make predictions something can check, users confirm the top, experts their layer, tests execution, each correction a commit.“If the plan requires the graph to be right, the plan fails.” § top
    Source code as a layered graphProvenance and evidence 99Synthetic users 26
  • hypothesisPatterns are findings: coding.sgit.ai and nfrs.sgit.ai rest on the hypothesis that a codebase's quality is visible in the shape of its graph, one class per file a tree, mirrored tests a symmetry, raw primitives a forbidden node type.“a codebase's quality is visible in the shape of its graph.” § top
    Patterns are findingscoding.sgit.ai 5nfrs.sgit.ai 10
  • hypothesisWho buys it is anyone generating code faster than they can review it, especially teams whose review is a compliance requirement; what is defensible is the record and the loop, not the model, which will be a commodity.“What is defensible is the record and the loop, not the model.” § top
    Startups and early access 34The record 57Strategy and positioning 26

Definitions (5)

  • definitionSource code is a fractal semantic graph, not as a metaphor: layers within layers, each a graph with its own node types and verbs, stories, flows, components, classes, methods and calls, the syntax tree, and below that bytecode and the machine.“It has layers within layers, and each layer is a graph with its own node types and verbs” § top
    Fractal semantic graphs 62Code review 18Source code as a layered graph
  • definitionA refactor should change the method and syntax layers and leave class shapes, commands and stories untouched; if the story layer moved, the claim is wrong, visible without running anything.“If a change claims to be a refactor and the story layer moved, the claim is wrong, and you can see that without running anything.” § top
    Code review 18Refactor or fix, by shape
  • definitionA bug is a story that stopped holding; its fix moves the bottom layers and is visible at the top as the story holding again, usually with a new test: bodies moved, signatures and fields still, a test added.“The shape is: bodies moved, signatures and fields still, a test added.” § top
    Code review 18Refactor or fix, by shape
  • definitionThe blast radius of a change is the climb: from the methods touched, up through callers including dynamic dispatch, to the commands and stories, the same idea as for agents, where footprint is what happened and blast radius what could.“the footprint is what happened, the blast radius is what could.” § top
    Blast radius 36Footprint 22Code review 18
  • definitionA method stream, from June 2012, is a code representation of an entire call tree: one file with the original method and all the methods it calls, recursively, which is how code was reviewed on the O2 Platform.“MethodSteams are a code representation of an entire call-tree, i.e. one file that contains the original method and all the methods it calls (recursively).” § top
    Code review 18The OWASP O2 Platform 5Dinis Cruz 126

Limits (3)

  • limitWhat the example does not do: the stories are hand-written, call resolution stops at the repository's edge, the syntax tree is fingerprinted per method but not diffed node by node, and it is one language with unusually strong conventions.“It is one language with unusually strong conventions, which makes the class layer easy; a second language is the test of whether the layers hold their shape.” § top
    Code Review Graphs 4Source code as a layered graph
  • limitWhat does not exist yet: a model proposing stories and unresolved edges, a node-level syntax diff, a second language, the interface layer, test paths compared to predicted streams, and above all the review that sits on a pull request.“Everything in the previous sentence is a project a competent team could start on Monday, and the first of them is the one I would start with.” § top
    Code review 18Source code as a layered graph
  • limitThe example uses a parser and not a model, deliberately, so that every number in it is checkable; the article says where a model goes on top.“it uses a parser and not a model, so that every number in it is checkable” § top
