The article: Agent hooks in October 2026: a technical debrief on what each platform lets you see, stop and change, where hooks run, and where they fail (2026-10-14). Every claim below is the article's own, in plain words, with the sentence it rests on and a link to its section.

Facts (18)

  • factThe technical people trying to control agents for real are reaching for hooks: small programs the agent's harness runs at fixed points, before and after a tool call, when a prompt is submitted, when the agent stops.“small programs the agent's harness runs at fixed points, before a tool call, after it, when a prompt is submitted, when the agent stops” § top
    Agent tooling 32Hooks are kernel code 14
  • factThe tools differ where it matters for security: whether an organisation can force its own hooks, whether a failing hook blocks or lets the action through, whether repository hooks need trust, and whether anything sees the model's output.“The design has converged; the security properties have not.” § top
    Agent tooling 32Hope or enforcement 65
  • factThis site already runs on hooks: one prints the agent's written policy back after every summary, and another appends the status report at the end of its answers.“This site already runs on them.” § what
    Memory and context 46Behaviour policy 91The SGit Newsroom 72
  • factAnthropic has the richest surface, an allowManagedHooksOnly setting, and since version 2.1.295 an onFailure block option, because a policy hook with a wrong path or a crashing script lets everything through.“a policy hook with a wrong path or a crashing script lets everything through” § platforms
    Anthropic 45Claude Code 49Fail closed 2
  • factCodex has hooks with a managed-only option, hosted tools such as web search not covered, and docs that call hooks a useful guardrail, not a complete enforcement boundary; ChatGPT has admin controls rather than hooks.“Treat tool hooks as a useful guardrail, not a complete enforcement boundary.” § platforms
    OpenAI 20Codex 6ChatGPT 22Hope or enforcement 65
  • factGemini CLI is the only coding agent with documented hooks around the model call itself, BeforeModel and AfterModel, and it warns that project-level hooks are risky when opening untrusted projects.“The only coding agent with documented hooks around the model call itself” § platforms
    Google 40Gemini 12Agent tooling 32
  • factGitHub Copilot lets organisations install machine-wide policy hooks that load before all others, but command hook timeouts are always fail-open, even for admin-deployed policy hooks.“Command hook timeouts are always fail-open, even for preToolUse and admin-deployed policy hooks.” § platforms
    GitHub 32GitHub Copilot 11Fail closed 2
  • factCursor has hooks at four levels, Enterprise, Team, Project and User; crashes, timeouts and exit codes other than 2 fail open by default, with a failClosed option recommended for MCP hooks.“Crashes, timeouts, and non-zero exit codes other than 2 fail open by default” § platforms
    Cursor 4Fail closed 2
  • factOn most tools a hook that crashes, times out or returns something malformed lets the action through; a security hook with a bug is no hook at all unless fail closed is set.“A security hook with a bug is no hook at all” § fail
    Fail closed 2Hope or enforcement 65
  • factHooks only see what is routed through them: Anthropic's tracker has a case where a hook blocked an edit and the agent made the change through a tool the hook did not cover, closed not planned.“the agent made the change through a different tool the hook did not cover” § fail
    Agent tooling 32Reach 47Anthropic 45
  • factHooks run with the user's full permissions beside an agent with the same, so unless installed where the agent cannot write, the agent can change the files that define them.“execute shell commands with your full user permissions” § fail
    Hooks are kernel code 14Claude Code 49
  • factHooks shipped in a repository are an attack surface: Check Point's Caught in the Hook, 25 February 2026, found hook commands in project settings ran automatically without confirmation, since patched.“hook commands defined in .claude/settings.json will run automatically without confirmation” § fail
    Check Point ResearchClaude Code 49Supply chains 22
  • factIn a headless or SDK run Claude Code never shows the trust dialog and treats the folder as trusted, so a repository's hooks run unreviewed; and most hooks cannot see the model's output.“treats the folder as trusted” § fail
    Claude Code 49Hooks are kernel code 14
  • factThe people who build hook collections agree: Trail of Bits says hooks are not a security boundary, guardrails not walls, and cc-safety-net says it is not a sandbox and a broken config never blocks anything.“The people who build hook collections agree.” § fail
    Trail of Bits 2Prompt injection 26Isolation and agent desktops 28
  • factIn a throwaway repository a project-level hook implementing one rule of the site's policy stopped a push to a disallowed remote in a real headless run, and asked to try other ways the agent declined.“the hook stopped the push to the other remote, and nothing arrived there” § test
    Claude Code 49Hope or enforcement 65Dinis Cruz 126
  • factThe headless run also loaded the owner's user-level hooks, because hooks follow the user, and a status counter that reads command text counted the throwaway commit as the site's.“a hook that infers behaviour from text cannot tell one repository from another” § test
    Agent tooling 32
  • factOWASP's GenAI Security Project hosts the Agent Control Standard, built on declarative hooks: a separate guardian answers allow, deny, modify, ask or defer, using policy engines such as OPA or Cedar.“a separate guardian inspects what an agent is about to do, and answers with allow, deny, modify, ask or defer” § standard
    OWASP 13Agent Control Standard 2Open Policy Agent 7Cedar 7

Proposals (1)

  • proposalAs a defender: make the organisation's hooks the only hooks, fail closed, hook every path to the same effect, watch the configuration, review repository settings before a headless run, and pair hooks with a boundary.“Hooks decide; the boundary holds.” § defend
    Isolation and agent desktops 28Fail closed 2Hooks are kernel code 14

Definitions (1)

  • definitionA hook is a program the agent's harness runs at a fixed point in its loop, with the event on its input and a decision on its output; the pre-tool hook sees the tool and its full input and can allow, deny, ask or rewrite.“A hook is a program the agent's harness runs at a fixed point in its loop” § what
    Agent tooling 32
