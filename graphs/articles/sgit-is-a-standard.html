The article: sgit is a standard, not a server: everything in a vault is one hash away, any storage can serve it, and the server is the least interesting part (2026-10-16). Every claim below is the article's own, in plain words, with the sentence it rests on and a link to its section.

Facts (19)

  • factGit is not GitHub; it is a format of blobs, trees, commits and refs named by their hashes, which GitHub, GitLab, a bare repository and a folder on a laptop all implement.“Git is not GitHub. It is a format: blobs, trees, commits and refs, named by their hashes, laid out in a way any tool can read.” § git
    Git 17GitHub 32A standard, not a server
  • factPeople read encrypted git and picture a product with a server in the middle; there is a server, and it is the least interesting part.“There is a server, and it is the least interesting part.” § git
    A standard, not a serversgit 91
  • factEvery object except the ref and the branch index is named by the SHA-256 of its own ciphertext, so a name can never point at different bytes and anyone can keep an object for ever.“Every object except the ref and the branch index is named by the SHA-256 of its own ciphertext, so a name can never point at different bytes” § vault
    SHA-256 15Vault design 48Encryption and keys 70
  • factThe name says which is which: an immutable object's id is obj-cas-imm- and a hash, the mutable pointers are ref-pid-muw- and a hash, so a cache can keep an object without reading it or a header.“An immutable object's id is obj-cas-imm- and a hash; the mutable pointers are ref-pid-muw- and a hash.” § vault
    Vault design 48
  • factsgit keeps no deltas between versions of a file; a changed file is a new object, a trade made so anyone can cache without asking.“sgit keeps no deltas between versions of a file; a changed file is a new object.” § vault
    Vault design 48
  • factThe vault key gives the vault id and, one way, the read key; the read key cannot be turned back into the write key, so it can be published.“The read key cannot be turned back into the write key, so it can be published.” § one-hash
    Encryption and keys 70
  • factThe read key gives the ref's name: the first twelve hex characters of an HMAC of the read key over sg-vault-v1:file-id:ref: and the vault id, so the server never told you where the head is.“In the CLI's code it is the first twelve hex characters of an HMAC of the read key over sg-vault-v1:file-id:ref: and the vault id.” § one-hash
    Encryption and keys 70Vault design 48
  • factWriting is the same objects PUT in batches, plus one compare-and-swap on the ref and the branch index.“Writing is the same objects, PUT in batches, and one compare-and-swap on the ref and the branch index.” § one-hash
    Vault design 48
  • factTwo independent implementations speak the format, the CLI and the browser vault app, and each verifies the other's changes.“Two independent implementations speak this format: the CLI, and the browser vault app” § one-hash
    sgit 91A standard, not a serverClient-side and on-device 56
  • factAny storage that answers a GET implements the read half of the convention: an S3 bucket, a CDN, GitHub Pages, a folder, Python's one-line file server.“any storage that answers a GET implements the read half of the convention: an S3 bucket, a CDN, GitHub Pages, a folder, Python's one-line file server.” § storage
    Amazon Web Services 30GitHub Pages 9Python 11Deployment and self-hosting 21A standard, not a server
  • factStripped down, the API has two jobs: protect writes with an access token and the compare-and-swap, and shorten reads a little with batches of fifty objects and a listing.“the API has two jobs: protect writes, with an access token and the compare-and-swap, and shorten reads a little, with batches of fifty objects” § storage
    A standard, not a serverDeployment and self-hosting 21
  • factEvery deployment option is shipped: a folder, a laptop running the hosted image with sgit serve in Docker, Podman or Python, your own server, a static host, or the hosted service, a Lambda in front of S3 behind CloudFront.“a laptop, with sgit serve running the hosted service's own image in Docker, Podman or a plain Python process” § storage
    Docker 8Amazon Web Services 30Deployment and self-hosting 21
  • factThe cache layer is shipped: sgit cache add declares a path, and every push keeps an encrypted cache object for it at a location derived from the read key and the path, so a reader needs no walk.“every push keeps an encrypted cache object for it at a location derived from the read key and the path.” § cache
    Vault design 48sgit 91
  • factA miss or a stale cache entry falls back to the ordinary walk, so correctness never depends on the cache; losing one is a performance problem, never a correctness one.“A miss or a stale entry falls back to the ordinary walk, so correctness never depends on the cache” § cache
    Vault design 48
  • factThe cache layer is Scion's derived data, built by the writer instead of a server and named by the key instead of indexed by it.“This is Scion's "derived data", built by the writer instead of a server, and named by the key instead of indexed by it.” § cache
    Scion 3Anthropic 45Vault design 48
  • factsgit keeps history, blame and merges on the client, and would even if the server could read, because a merge is a workflow step that needs the context, the history and the policy on who may merge.“a merge is a workflow step that needs the context of the change, the history and the policy that says who may merge what.” § client
    Client-side and on-device 56Multi-agent designs 62Scion 3
  • factScion's post concedes the point from the other side: it could not keep a merge queue at its rate, so concurrent changes can conflict and Claude typically fixes them.“concurrent changes can conflict, but Claude can typically fix these conflicts” § client
    Claude 66Scion 3Multi-agent designs 62
  • factsgit keeps the property that made git git, a full clone as a complete verifiable copy, but the full clone became optional through folder scope, history depth, sparse clones and the cache layer.“What changed is that the full clone became optional.” § client
    Vault design 48Git 17
  • factNone of this was a plan to be minimal: because the server cannot read a byte, every feature had to be expressible as objects a writer produces and a reader derives, which is why the designs are small enough to be a standard.“None of this was a plan to be minimal. The server cannot read a byte, so "just do it on the server" was never available” § constraint

Hypotheses (1)

  • hypothesissgit is the same kind of thing as git, a standard rather than a server, and the owner thinks that is the most important thing to understand about it.“sgit is the same kind of thing, and I think that is the most important thing to understand about it.” § top
    sgit 91A standard, not a serverDinis Cruz 126

Definitions (2)

  • definitionA vault is a set of files laid out by a convention: four kinds of object, all ciphertext, blobs, trees, commits and one mutable pointer per branch.“A vault is a set of files laid out by a convention. Four kinds of object, all ciphertext: blobs, the file contents; trees, a folder's encrypted names pointing at blob and tree ids” § vault
    The vault 108Vault design 48
  • definitionA standard is a format with more than one implementation that agree.“That is what a standard is: a format with more than one implementation that agree.” § one-hash
    A standard, not a server

  • limitsgit is not a formal standard: no standards body, a documented format with two implementations.“Not a formal standard. No standards body; a documented format with two implementations.” § limits
