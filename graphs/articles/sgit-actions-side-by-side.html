Proposals (9)

  • proposalsgit in GitHub Actions needs its own repository and website, not a corner of another project: its own issues, its own CI pipeline, and a site that publishes what each run found.“That needs its own repository and its own website, not a corner of another project.” § why
    The brief 45GitHub Actions 10sgit 91
  • proposalOn every run the same small build output travels from a build job to a test job and a release job four ways, in parallel.“the same small build output travels from a build job to a test job and a release job, four ways, in parallel” § lanes
    Vault design 48The brief 45
  • proposalLane one, a vault server: the keys are in the repository's secrets, each job clones only the folders it needs with --path, and pushes back.“The keys are in the repository's secrets, each job clones only the folders it needs with --path, and pushes back.” § lanes
    Identity and secrets 59Vault design 48
  • proposalLane three, published as files: the encrypted objects on any web host, cloned read-only with sgit's static transport, which reaches any GET host; no server and no write path.“cloned read-only with sgit's static transport, which reaches "any GET host, read-only".” § lanes
    Deployment and self-hosting 21sgit 91
  • proposalEach lane reports the wall time per job and run, the bytes downloaded and on disk, which keys each job held and therefore what it could have read, and a screenshot of the result.“which keys each job held, and therefore what it could have read; and a screenshot of the result.” § report
    Footprint 22The brief 45
  • proposalThe repository should have a budget, with every token spent by a model step counted against it per run and per provider, and the same step run on more than one provider.“the repository should have a budget, and every token spent should be counted against it, per run and per provider.” § budget
    A token budgetThe brief 45
  • proposalThe failures become issues: large files without cloud storage, a headless clone fetching a file, concurrent full clones, each with a reproduction checked on every release.“The failures as issues. Large files without cloud storage, a headless clone fetching a file, concurrent full clones: each an issue with a reproduction, checked on every release.” § brief
    Complexity and shipping 60The brief 45
  • proposalKeys only in secrets, never in a workflow file, a log or an artefact's name; every artefact and published file is ciphertext; read keys may be published, write keys never.“Keys only in secrets, never in a workflow file, a log or an artefact's name.” § brief
    Identity and secrets 59Encryption and keys 70
  • proposalThe budget is a hard limit, not a report after the fact.“And the budget is a hard limit, not a report after the fact.” § brief
