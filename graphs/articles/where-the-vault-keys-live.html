Facts (18)

  • factEvery vault on the site is encrypted in the client, so the server never sees a key and the key is the whole question.“the server never sees a key and the key is the whole question” § top
    Encryption and keys 70sgit.ai 62
  • factThe owner's agents now create vaults several a day, and keeping track of the keys has become a real problem.“Now my agents create vaults all the time, several a day, and keeping track of the keys has become a real problem.” § top
    The vault 108Identity and secrets 59
  • factAll vault data is stored in S3 as encrypted objects, served by an SG/Send API server on Lambda behind CloudFront.“All the data is stored in S3 as encrypted objects: commits, trees and files.” § architecture
    Amazon Web Services 30sgit 91
  • factIn the browser the vault key sits after the hash in the URL, which browsers do not send to the server, so decryption happens on the reader's machine.“browsers do not send that part of a URL to the server” § architecture
    Client-side and on-device 56sgit 91
  • factThe read key is the site's whole publishing model: read keys are published on purpose and vault keys never are.“The rule is short: read keys yes, on purpose; vault keys never.” § keys
    Encryption and keys 70The publishing method 42
  • factAppend tokens and PKI key pairs are separate credentials that each do one job, so a sender never needs the vault key.“Both exist so that a sender never needs the vault key at all.” § keys
    Identity and secrets 59Vault design 48
  • factThe agent that made a vault seals its key to the registry's public key and sends it with one POST to an append lane, using a write-only token issued to that sender alone.“It sends it with one POST to the registry's append lane, using a write-only token that was issued to that sender alone.” § handover
    Vault design 48The vault of vaultssgit 91
  • factA key that disagrees with one the registry already holds is set aside for review and never applied over the old one.“A key that disagrees with one it already holds is set aside for review, never applied over the old one.” § handover

  • factThe handover prompt gives the reason before the instruction and gives the agent a way out: seal the key and hand over the file, or hand over the key to be relayed.“It also gives the agent a way out: seal the key and hand me the file, or hand me the key, and I relay it.” § handover

Hypotheses (1)

  • hypothesisThe best long-term answer is public and private keys for every party, so a key is shared by sealing it to the recipient's public key.“For me the best long-term answer is public and private keys for every party” § next

Proposals (3)

  • proposalPassword manager integrations are the answer wanted for keys people hold; an open call was published and has not yet been followed up.“I have not followed it up yet, so the silence so far is mine, not theirs.” § next
    Identity and secrets 59
  • proposalsecrets.sgit.ai is a secrets manager that runs entirely in the browser and is unlocked by a passkey, whose PRF output derives the wrapping key for the keyring.“a secrets manager that runs entirely in the browser and is unlocked by a passkey” § next
    secrets.sgit.ai 8WebAuthn and passkeys 15Bitwarden Send 4Client-side and on-device 56
  • proposalDecryption out of band, where you send ciphertext and get plaintext back after proving who you are, is an idea and not yet a design.“That is an idea, not a design yet” § next
    Encryption and keys 70Deployment and self-hosting 21

Questions (2)

  • questionPKI raises the question of how an agent gets its private key in the first place; the workaround today is a fresh signing key per session pinned by the recipient.“how does an agent get its private key in the first place?” § next
    Identity and secrets 59
  • questionThe owner asks how other people manage their vault keys, or the keys of whatever encrypted system they use with agents.“I would be very interested in how other people manage their vault keys” § yours
    Identity and secrets 59RiskMandate 97

Definitions (2)

  • definitionA vault key is the one secret and carries read and write; a read key and a write key are derived from it one way.“It is the one secret, and it carries read and write.” § keys
    Encryption and keys 70sgit 91
  • definitionA lane is a write-only channel attached to a vault: one POST from anywhere, readable only by the vault's owner, with the server keeping only hashes of tokens and keys.“A lane is a write-only channel attached to a vault.” § lanes
    Vault design 48sgit 91

Decisions (2)

  • decisionVault keys live in two places today: a password manager for keys a person holds, and a registry vault run by its own isolated Claude session.“The registry is a private vault, run by its own Claude session that I keep isolated from everything else” § today
    The vault of vaultsIdentity and secrets 59Claude 66
  • decisionA key for another agent travels in one of three imperfect ways, and the pattern used most is the agent making its own vault and sending the key back on a lane.“which is why that last pattern is the one I use most” § agents
    Identity and secrets 59Multi-agent designs 62

Limits (4)

  • limitThe password manager integration does not exist yet, so today a key is copied and pasted into an entry by hand.“The integration does not exist yet (more on that below), so today this is a careful copy and paste into an entry of the right kind.” § today
    Identity and secrets 59
  • limitThe weakest step is getting a key into an agent session safely, because the agent platforms do not have secrets per session.“The hard part is getting the key into the session safely, because the platforms do not have secrets per session.” § agents

    secrets.sgit.ai 8
