Hypotheses (1)

  • hypothesisThe more a prompt insists that a value is a secret to be handled carefully, the more likely the model is to refuse to use it at all.“the more a prompt insists that a value is a secret, to be handled carefully and not exposed, the more likely the model is to refuse to use it at all” § pain
    Identity and secrets 59Agent tooling 32

Proposals (5)

  • proposalThe design flips the usual direction: the recipient makes a key pair where it runs, and only the public half leaves, by QR code, link or paste.“The recipient makes a key pair where it runs.” § design
    The recipient makes the keyEncryption and keys 70
  • proposalThe recipient downloads once, checks the owner's signature against a pinned key, and pipes the result into the tool, so the secret never enters the prompt, the transcript or the model's context.“the secret travels from the drop to the tool through a pipe, and never enters the prompt, the transcript or the model's context” § design
    Into the tool, not the chatMemory and context 46
  • proposalOne site, one job: a separate site on SG/Send's transfer API for handing secrets and public keys to agents and browsers, with all cryptography in the browser or the command line.“A separate site, built on SG/Send's transfer API, for handing secrets and public keys to agents and browsers.” § brief
    sgit 91SealDropClient-side and on-device 56
  • proposalRetire the friendly code: a short code is only safe inside a key exchange built for it, as Magic Wormhole does.“The friendly code is retired; a short code is only safe inside a key exchange built for it, as Magic Wormhole does.” § brief
    Magic WormholeEncryption and keys 70
  • proposalPairing for new sessions: a session with no key yet shows a fingerprint and a QR code, and the owner approves it from a phone.“A session that has no key yet shows a fingerprint and a QR code; the owner approves it from a phone.” § brief
    The recipient makes the keyIdentity and secrets 59
