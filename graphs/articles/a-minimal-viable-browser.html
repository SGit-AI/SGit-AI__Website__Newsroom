Hypotheses (3)

  • hypothesisA browser for one agent is a practical prompt-injection defence: an agent cannot leak what its browser cannot reach, and the grant shrinks to the mandate.“An agent cannot leak what its browser cannot reach.” § agent
    Prompt injection 26Reach 47Blast radius 36The minimal viable browser
  • hypothesisMozilla is better placed than anyone to build this: it has its own engine, privacy is its brand, it runs on the client, and its money does not come from knowing more about its users.“I think Mozilla is better placed than anyone to build this, for four reasons.” § why-mozilla
    Mozilla 5Strategy and positioning 26Privacy and sovereignty 45Client-side and on-device 56
  • hypothesisThe pitch to Mozilla should be speed, not security: a browser with only the code it needs starts at once, uses a fraction of the memory, and an agent can run many of them.“The pitch to Mozilla should not be security.” § speed
    Strategy and positioning 26Mozilla 5The minimal viable browser

Proposals (1)

  • proposalEvery extension in its own box gets only the sites and the powers its job needs, a change is a new request not a silent update, and the permission model is an Agent Behaviour Policy in all but name.“An extension in its own box gets only the sites and the powers its job needs” § extensions
    Behaviour policy 91The minimal viable browser

Definitions (1)

  • definitionA minimal viable browser has a small kernel, reviewed hardest and changed least, and loads components only when a page or an agent needs them, so its attack surface grows only as it is used.“A minimal viable browser has a small kernel, reviewed hardest and changed least” § top
    The minimal viable browserThe code you do not ship 18
