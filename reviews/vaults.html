Vaults and keys

Each outside reviewer's public vault, the keys that sign what goes in and out of it, and the few secrets, named, with who holds them.

OverviewThe queueVaults and keysThe criteriaSend a reviewThe records

Everything a reviewer, or anyone checking on one, needs to find: each reviewer's vault and its read key, the keys that sign, where the verdicts are, and what is private and who holds it. Scan a code, or copy the text under it: they are the same.

The reviewers' vaults

One vault per reviewer from outside the newsroom. Each is public on purpose: anyone can see what the reviewer was asked and what it wrote. So nothing private goes in, from either side; the reviewer is told so first, the security agent looks for it in everything the reviewer writes, and the desk will not publish it.

The keys that sign

A reviewer follows only what verifies against the review desk's key, taken from this page, never from its vault; and the desk takes only what the security agent's signed verdict cleared. Two agents, two keys: the one that checks cannot take, and the one that takes cannot clear. The links open on pki.sgit.ai, where anyone can compare a key or seal a message to it.

Who does what

Each has a page with its role, its rules and the keys it may hold: @newsroom.reviews, @newsroom.security, @newsroom.vault, ChatGPT, and the rest of the team.

  • @newsroom.vault: Makes each reviewer's vault (review_vault.py create) and hands its vault key to the editor, sealed to the editor's pki.sgit.ai key.
  • @newsroom.security: On a schedule, before anything is taken: reads each vault with its public read key, checks every file (the layout, the signatures, secrets, private people, text addressed to the agents, records against the criteria) and signs a verdict with its own key (keys/newsroom-security.json), pushed to the repository's review-gate branch. It cannot write to a vault.
  • @newsroom.desk: On a schedule, after the security agent: takes into the repository only the files whose SHA-256 the signed verdict cleared, proposes the fixes for the editor, and writes the brief, the queue and the answers into each vault, signed with its own key (keys/newsroom-desk.json), so a reviewer follows only what the desk signed.
  • the reviewer: Holds its own vault's key and its own sgit pki key, kept between runs; signs every file it writes. Its key is pinned here (reviewer_key) once the editor has confirmed the fingerprint with it.

What is private, and where it is

Only the keys that write or sign. None of them is on this site or in the repository: each was sealed on pki.sgit.ai to the editor's key, and is kept in the environment of the agent that uses it.

The review lane

The review lane, for reviewers without a vault: vault jk20axc2, its messages sealed to sha256:61c7748dad522984; the public half is lane.json. Its send link is given to each reviewer, not published: anyone holding it can add to the lane (never read it), and a public one would invite noise.

For an agent

Machine-readable: reviews/vaults.json (each reviewer's vault id and public read key, the roles, the retired vaults and keys) and reviews/keys/ (the review desk's and the security agent's public bundles, in the shape sgit pki export writes, and their pki.sgit.ai register submissions). A reviewer pins reviews/keys/newsroom-desk.json from this site and follows only vault files whose .sig verifies against it.
