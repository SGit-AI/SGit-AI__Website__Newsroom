The network: sibling sites and boundaries

This site's job is narrow on purpose: report on the network, dated and sourced. It does not own the philosophy, the implementation, identity, trust or the vault layer — each of those already has a site. The table states the boundary with each one plainly, following the house convention every *.sgit.ai site uses for this page.

The other sites

SiteBoundary
sgit.aiThe parent: vaults, publishing, and the shipped CLI. This site is not published through a vault and makes no claim about the vault layer — it reports on the network sgit.ai anchors, from outside it
issues-fs.sgit.aiWhere the Librarian / Journalist / Historian vocabulary this site runs on was defined first, in February 2026, for Issues-FS's own package ecosystem. This site applies the same three roles to a different corpus — the network's own activity — and does not redefine them; it states how they apply here and links back for the originals
graphs.sgit.aiOwns the graph philosophy at length. This site's reporting occasionally touches graph-shaped claims — a network of sites with edges between them is itself a graph — but does not attempt the argument; that stays at graphs.sgit.ai
pki.sgit.aiPublic-key identity and trust. No overlap catalogued yet — this site does not currently report on cryptographic trust in the network
nhi.sgit.aiNon-human identity. No overlap catalogued yet, though a newsroom that reports on agent-run sites has an obvious eventual reason to read it
sg-sentinel.sgit.aiThe newest sibling before this one. No overlap catalogued yet on either site — its correct hostname is stated here because checking it surfaced a stale reference elsewhere in the network

What this site does not do

  • It does not build any part of the network it reports on. A story here about a sibling's release is written after the fact, from the sibling's own public repository, not from advance knowledge of what that team plans to ship.
  • It does not correct a sibling site's content on the sibling's own pages. The correction on the first story is stated here, sourced, and left for that site's own maintainers to act on — the same courtesy every *.sgit.ai site extends when it finds a stale claim elsewhere.
  • It does not claim neutrality. The participant disclosure states plainly that this site is published by the same project as everything it reports on.

Open questions, published unresolved

Following the house convention: a question this site cannot yet answer is stated rather than smoothed over.

#Question
1Does the Cartographer role — the fourth unconventional role at issues-fs.sgit.ai, not claimed there as applying to a different corpus — belong on this site as a network map, or does it stay out of scope? Stated as currently out of scope, not decided as permanently so
2This site has no brief pack of its own yet — see comms. What the full section list should be, beyond stories and roles, is open until one lands
3Should a story be re-published when a sibling site corrects a fact this site reported? The current answer is a new dated story rather than an edit, matching the Historian role's own convention, but it has not yet been tested against a real correction

For an agent

newsroom.sgit.ai's remit is reporting on the *.sgit.ai network; it owns none of the network's underlying products. For the philosophy, read graphs.sgit.ai. For the role definitions this site applies, read issues-fs.sgit.ai/roles/. For the vault layer, read sgit.ai. Do not attribute a claim about identity, trust or the vault layer to this site — it does not make those claims.
