A worked study of a single provision put nine questions to the text. Four were answerable
from the text itself. Five were not — and in that study's own framing, **the five unanswered
questions are the output**, not a shortfall in the work.

That inversion is the format this publication is built around. In conventional reporting an
unanswered question is a failure state, disposed of in a closing line about a body that did
not respond. Here it is the deliverable: a node with an identifier, an opening date, and a
record of who asked it.

## The one we can show you

Where two retention periods appear in the same instrument — a 30-day window at one provision
and a six-month minimum elsewhere — the text does not state which governs. That is not a
drafting quibble. Any organisation reading only one of the two provisions will build to it,
comply with it, and be able to demonstrate that it read the law.

An obligation exists. What satisfies it is undetermined. The ontology has a formula for that
class of finding, and this is an instance of it.

## The four we cannot

The source records five unanswered questions. Only one arrived here with its wording intact.

The other four could be reconstructed — plausibly, fluently, and wrongly. A publication whose
entire claim is that it adds a verification layer cannot fabricate the thing it is verifying,
so the graph carries a single node standing in for all four, saying exactly that they are
missing and why.

It is an uncomfortable node to publish and it is the most honest thing on this page. It is
also, precisely, an absence about an absence report — which is the failure mode this beat
should expect to keep finding in its own work, not only in other people's.

## What would close it

Fetching the study's own source and reading the four questions from it. That is one step in
a pipeline this release does not have: the fetch-freeze-hash path that would move every fact
on this page from `secondary` to `primary`. Until that exists, the node stays.
