SGit Newsroom · Issue 5 · 2026-10-11

No server, by design: a newsroom that runs in your browser, a model in the tab, and the agents that read, test and draw for it

By Dinis Cruz, written with the Journalist

Abstract: Everything in the last two issues runs in the reader's browser. First the database was retired and the file system took its place; now the back end is retired too, and what is left on the server side is commodity that holds no logic and cannot read the data. Eight articles on how that works and what it makes possible. Why there is no server, and why that made a business decision possible; Chrome's model in the tab, the hardest remaining piece; where the vault keys live and an RFC for keys a reader cannot write with; and the agents that do the newsroom's work: five readers sent through every article, synthetic users driving a real browser, image models judged blind, and a governance framework kept as a graph.

The reading meter, the personas, the newsroom of your own, the encrypted sharing: none of it runs on a server. This issue is about why, what that takes, and the agents that do the work around it. It is the third of three on what was published between 9 and 11 October, after pay after you read and authority outside the model.

No server, by design

No server, by design is the decision in two steps. First the database was retired: the file system is the database, and every intermediate result is a file you can version, diff and read. Now the back end is retired too: the application moves to the browser. What is left on the server side is commodity, static hosting, a vault server that stores ciphertext it cannot read, a payment link, and each is a product, not code of mine:

It is no servers of mine with logic in them.

It is also what made the reading meter's business decisions possible: a server cannot read the reader's data, so anything that needs to has to happen where the key is, and the gaps that leaves are written down rather than closed.

A model in the tab

A model in the tab is about the hardest remaining piece. Chrome now ships a language model that any page can prompt, offline, on capable desktops. It is real and stable, it has rough edges, and the objections to it from other browser makers are serious. The way to build on it without being captured by it:

The way to build on it without being captured by it is to keep the meaning in the data, not in the prompt.

The keys underneath

If the server cannot read anything, the key is everything. Where the vault keys live is key management as it actually runs: one secret per vault and the keys derived from it, a password manager and a registry kept by its own agent, and new keys that travel sealed on a write-only lane instead of through a chat.

The key is the whole question.

RFC 0001 closes the gap that remains: today, whoever can read a vault can also produce data every client accepts. The obvious fix does not work, and what does is two key pairs, so that a reader cannot write and a host cannot forge, with fourteen questions for reviewers.

Two key pairs work.

The agents that do the work

A newsroom that runs in the browser still needs people, and agents, to make what it serves. Four articles on the agents that read, test and draw for it.

One article, five readers keeps the prose first, then sends five agents through each article once it is written: a librarian that catalogues every fact with the sentence it came from, a cartographer that maps the concepts, a historian, an explainer and a storyteller. Cataloguing everything turned them into fact-checkers nobody had asked for.

Keep writing the article first.

How to run synthetic users is a how-to from three studies: invented readers with a situation and a question, driving a real browser one screenshot at a time, saying what they see and think. The rule that makes it work:

Give the agent the screenshot, not the page's code.

The infographic bake-off gave every image model on OpenRouter the same eleven briefs, judged 101 images blind, and recorded every cost, $10.44 in all, to answer which model for which kind of picture.

And the AI governance stack as a graph takes Hari Kota's ten-layer stack, keeps it exactly as posted, and makes the graph underneath it the model, with 119 edges between the layers, each citing the provision it rests on:

A gap is a missing edge, and a missing edge is a query.
